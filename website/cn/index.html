敏感信息，发往模型前就被挡住

数据库口令、API Key、SSH 私钥不会因为一次 Agent 读文件就离开你的机器。 OwnCoder 在请求发出前自动检测并替换为 ***。

识别 password、secret、token 以及 *_PASSWORD 等环境变量后缀，减少漏网。

两种脱敏粒度

  • 值级脱敏：仅掩码敏感字段，其余结构仍可读，Agent 能理解配置形态。
  • 全文件脱敏：私钥、证书等整文件掩码，Agent 只知道“这是敏感文件”。
  • 可自定义规则：在设置中追加 glob 与正则，并支持本地预览验证。

核心能力

安全之外，更省token

三大省 Token 优化：双模型分阶段使用、缓存命中率最大化、让 LLM 多做事少说话。

双模型省 Token

原理：任务分解阶段消耗 Token 较少但需要强规划能力；执行阶段包含大量工具调用和迭代但对推理要求相对较低。

配置：Plan 阶段用高能力模型（GPT-4 / Claude 3.5 Sonnet），Agent 执行阶段切换至成本更低的模型（GPT-4o-mini / Claude 3.5 Haiku / DeepSeek / 通义）。

收益：执行阶段通常占总 Token 消耗的 70-80%。将其交给成本更低的模型可显著降低总费用，同时让高能力模型专注于关键决策。

提示词结构优化：最大化缓存命中率

原理：许多模型服务商支持提示缓存（Prompt Cache），对重复出现的输入 Token 按更低价格计费。OwnCoder 的提示词拼接策略专门针对缓存优化设计。

实现：不变内容前置（系统提示词 + 工具定义、平台信息、项目规则），变动内容后置（用户输入、任务分解结果）；固定部分拼接顺序与格式严格一致，确保跨轮次缓存前缀完全匹配。

效果：系统提示词和工具定义自动享受缓存；重复的项目上下文命中率可达 60-80%。实测缓存命中率可达 95%，让高频使用场景更经济。

让 LLM 多做事，少说话

原理：输出 Token 通常是输入的 2-3 倍价格。让 LLM 多做工作（通过工具调用）、少说话（减少解释性文字），可大幅降低输出成本。

纪律：关键规则是零叙事工具调用——默认直接调用工具完成任务，除工具调用外不输出任何文字。禁止过渡语、计划叙述、进度评论、寒暄、解释；禁止"让我先…""现在开始…""接下来…""我来搜索…""首先需要…"；禁止工具调用之间的任何说明文字。
