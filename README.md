# OwnCoder

English: [README_EN.md](./README_EN.md)

**安全、省 Token 的 AI 编程工具：文件脱敏保护敏感信息，贵模型拆解指导，便宜模型执行。**

---

## 为什么选择 OwnCoder？

使用 AI 编程工具，既要保护文件里的密码和密钥，也要控制反复读代码、改代码、跑验证带来的 Token 开销。OwnCoder 重点解决这两件事：

| 核心价值 | 实现方式 |
|----------|----------|
| **安全：文件脱敏** | 读取受保护文件时，先在本地掩码敏感值，再把脱敏结果交给模型；支持自定义文件规则和脱敏预览 |
| **省 Token、降成本：模型分工** | 贵模型理解需求、拆解任务并给出执行步骤，便宜模型按步骤完成代码修改与验证；结合按需检索和上下文缓存减少开销 |

### 🔒 安全：文件内容先脱敏，再交给模型

- **自动脱敏**：对规则覆盖的配置文件、凭证文件和私钥文件执行值级或全文件脱敏，以 `***` 掩码敏感内容。
- **本地处理**：文件脱敏、代码索引和检索在本地进行，脱敏不会改写磁盘上的原文件。
- **规则可配置**：可添加项目专属的敏感文件与检测规则，并在设置中预览脱敏结果。

使用远程模型时，任务所需的代码片段和上下文仍会发送给你配置的模型服务。脱敏保护的是规则覆盖的敏感内容，具体范围见下方说明。

### 💰 省 Token：贵模型负责拆解，便宜模型负责执行

**让贵模型指导便宜模型完成任务。** 贵模型先理解需求、整理约束并拆出有顺序的步骤；便宜模型再按这些步骤检索代码、编辑文件、执行命令和验证结果。消耗较多 Token 的执行循环可以使用低成本模型，贵模型的能力集中用在任务规划上。

配合按需读取代码和上下文缓存，既减少不必要的 Token 输入，也降低执行阶段的 Token 费用。

## 🔒 强大的安全防护体系

### 敏感信息自动脱敏

开启脱敏后，Agent 通过内建文件读取工具读取 `.env`、凭证配置、SSH 私钥等受保护文件时，会先在本地执行脱敏，再将结果返回给模型。匹配的敏感内容替换为 `***`，原文件保持不变。

**三层防护：**

| 层级 | 机制 | 覆盖范围 |
|------|------|----------|
| **文件匹配** | 60+ 内置 glob 模式识别敏感文件 | `.env`、`*credentials*`、`*.pem`、`*.key`、`kubeconfig`、`terraform.tfvars` 等 |
| **格式识别** | 25+ 种已知密钥格式的精确正则 | OpenAI `sk-...`、AWS `AKIA...`、GCP `AIza...`、GitHub `ghp_...`、数据库连接串、JWT、PEM 私钥块 |
| **关键词匹配** | 通用凭证关键词 + 大写环境变量后缀 | `password`、`secret`、`token`、`api_key`、`*_PASSWORD`、`*_SECRET`、`*_TOKEN` 等 |

**两种脱敏粒度：**

- **值级脱敏**（`.env`、`credentials.json` 等）：仅掩码敏感字段的值，其余配置内容保持可读，Agent 仍能理解文件结构。
- **全文件脱敏**（`*.pem`、`*.key`、`id_rsa`、`*.sqlite` 等）：非空行内容被掩码；对于部分键值行，会保留键名和分隔符，方便理解结构。

> 适用范围：值级检测规则只用于内置规则覆盖的敏感文件，普通源代码文件不会自动执行这些检测。自定义敏感文件规则采用全文件脱敏；`.env.example`、`.env.sample` 等模板文件在允许列表中，不参与脱敏。请通过预览确认项目中的敏感文件已被规则覆盖。

---

### 自定义脱敏规则

每个人的项目不同，敏感信息的形态也不同。在 **设置 → 安全** 中，你可以：

**1. 添加自定义敏感文件（glob 模式）**

逐行输入 glob 模式，匹配的文件将被**全文件脱敏**：

```
config/production.json
*.secret
my-custom-env.*
internal/keys/*
```

**2. 添加自定义检测规则（正则表达式）**

逐行输入正则表达式，匹配的内容将在值级脱敏文件中被掩码：

```
INTERNAL-\d{8}-[A-Z]+
my_company_[A-Za-z0-9]{32}
corp-secret:\s*\S+
```

规则会自动编译并追加到内置检测器之后，无效正则会被静默跳过。

**3. 脱敏预览测试**

点击"选择文件测试"，选择任意本地文件 —— 系统会用当前规则对它运行一遍脱敏引擎，展示：
- 匹配了哪些规则
- 每种规则命中了几处
- 脱敏后的内容预览

不用实际调用 LLM 即可验证脱敏效果。

### 文件写入与安全边界

内建文件工具允许 Agent 修改工作区内的文件，不再按文件类型、敏感文件、依赖目录、构建产物或锁文件设置写入保护策略。读取文件并发送给大模型前仍会执行敏感信息脱敏，本地文件内容不会因脱敏而被修改。

工作区路径仍会经过边界校验；Agent 命令中的潜在写入或删除操作仍会进入危险命令二次确认。

---

### 危险命令二次确认

Agent 执行 `rm -rf`、`git push --force`、`chmod 777` 等危险操作时，会弹出确认栏：
- 显示完整命令内容，一目了然
- **Enter 键不会通过** —— 必须手动点击"允许"
- Esc 或点击"拒绝"即撤销
- 窗口崩溃或 120 秒无响应 → **自动拒绝**（fail-closed）

## 💰 省 Token 与模型成本优化

### 贵模型规划，便宜模型执行

OwnCoder 支持为任务分解和执行循环分别配置模型与思考强度，让高能力模型产出的计划成为低成本模型的执行指导。

| 阶段 | 推荐模型 | 负责的工作 |
|------|----------|------------|
| **任务分解** | 能力更强、价格较高的模型 | 理解用户意图，整理相关历史和约束，将目标拆成有顺序、有依赖关系的执行步骤 |
| **循环执行** | 适合编码、价格较低的模型 | 按计划检索和读取代码、修改文件、运行命令与验证，根据结果继续完成任务 |

工作流程：**用户需求 → 贵模型拆解与指导 → 便宜模型按步骤执行 → 验证与交付**。

执行阶段通常需要多轮工具调用和结果反馈。将这部分交给便宜模型，可以降低大量执行 Token 的单价；清晰的任务步骤也有助于减少重复探索和无效尝试。实际收益取决于任务复杂度、模型能力和服务商定价。

**配置方式：**

1. 在 **设置 → 模型** 中添加所需模型。
2. 在设置中开启 **执行阶段单独配置**。
3. 在对话栏分别选择 **任务分解模型** 和 **循环执行模型**，并按需要调整各阶段的思考强度。

未开启分阶段配置时，任务分解与执行使用统一的模型配置。

### 按需读取与上下文缓存

- **按需获取代码**：通过符号搜索、文件大纲和局部读取提供相关代码，减少整文件进入上下文的 Token 消耗。
- **复用相关历史**：检索与当前任务相关的历史信息，减少重复提供背景和重复探索。
- **利用模型服务的上下文缓存**：缓存命中可降低重复输入的费用，具体计费方式以服务商为准。

## 核心功能

### 🧠 Plan + Agent 双模式

| 模式 | 能力 | 适用场景 |
|------|------|----------|
| **Plan** | 只读：分析代码、搜索、生成方案 | 需求分析、架构设计、代码审查 |
| **Agent** | 读写：编辑文件、执行命令、运行测试 | 功能开发、Bug 修复、重构 |



### 🧪 执行级验证引擎

Agent 改完代码后，自动运行真实的编译器/类型检查器/测试来验证：
- 类型检查：`tsc`、`mypy`、`go vet`
- 代码检查：`eslint`、`ruff`、`pylint`
- 测试运行：自动发现关联测试文件

验证失败时进入**自动修复循环**，根据编译错误自行修正。

### 📝 内联变更审查

每次 Agent 操作后，对话上方展示变更栏，逐文件 diff 对比：
- 独立"保留"/"撤销"按钮
- "全部保留"/"全部撤销"全局操作
- 点击文件名在 Monaco 编辑器中打开


### 📦 嵌入式代码检索

- **统一索引系统**：基于 SQLite + FTS5 的高性能全文索引
  - 符号搜索：支持 35+ 种语言（通过 tree-sitter）
  - 全文检索：FTS5 虚拟表提供快速关键词搜索
  - 经验索引：存储故障修复记录，跨会话复用
  - 增量扫描：智能更新，遵循 `.gitignore`
- **本地 RAG 嵌入**：三种后端（FastLocalEmbedding / NeuralEmbedding / ApiEmbedding），可离线使用

### 🧩 其他亮点

- **MCP 协议**：配置任意 stdio MCP 服务器，工具自动暴露给 Agent
- **子 Agent 协调**：层级任务分解，子 Agent 间通信共享记忆
- **经验学习**：Agent 记住过往修复模式，跨会话检索
- **@ 文件提及**：`@文件名` 提供上下文，支持自动补全
- **多会话并发**：同时运行多个 Agent 任务
- **双语设计**：中文界面 + 英文运行时提示词，面向中文开发者

## 快速开始

### 前置要求

- **Node.js** >= 20
- **pnpm**（`npm install -g pnpm`）
- **Windows**（当前主要支持平台）

> `.npmrc` 已配置 npmmirror 镜像加速下载。

### 安装与运行

```bash
git clone https://github.com/YOUR_ORG/owncoder.git
cd owncoder
pnpm install

# 为 Electron 重建原生模块（better-sqlite3、node-pty）
cd apps/desktop
pnpm rebuild
cd ../..

# 构建所有 TypeScript 包
pnpm -r run build

# 启动开发服务器
pnpm dev
```

> **为什么要 `pnpm rebuild`？** `better-sqlite3` 和 `node-pty` 是 C++ 原生模块，需要为 Electron 的 Node.js 版本编译。如果跳过此步，运行时会报 `NODE_MODULE_VERSION` 不匹配的错误。每次 `pnpm install` 后都需要重新执行。

### 连接大模型

OwnCoder 支持任意 OpenAI 兼容接口：

1. 打开 **设置 → Models**
2. 添加提供商：填写名称、Base URL、API Key
3. 在对话栏下拉菜单中选择你的模型

兼容 OpenAI、DeepSeek、通义千问、智谱、Moonshot 等所有 OpenAI Chat Completions API 服务。
