## 三、已确认现象

- 桌面端同时打开 2–3 个会话时，堆内存可增长到约 2GB 并触发 OOM。
- 单会话场景正常。
- 已有记录表明问题与 `runtime`、内存和 Electron 多会话场景相关。

## 四、当前分析结论

最可能的增长路径有两条：

1. **主进程 runtime 未及时卸载**：主进程虽然已有 `unloadIdleRuntime`，但会话切换或创建成功后未调用；渲染侧在 `bySession` 命中时又可能跳过 `switchChatSession`，使空闲 runtime 长时间保留。
2. **渲染侧按会话常驻缓存**：`bySession`、`history`、`liveEvents` 以及相关的 `queue`、`changes`、`plan` 缓存可能随会话累积，未及时清理。

已有修复记录中列出的处理包括：切换焦点后卸载上一个会话的 idle runtime、每次切换都调用 `switchChatSession`，以及清理无在途工作的空闲会话缓存。以上是代码分析结论，尚不能单独证明本次 OOM 的唯一根因。
